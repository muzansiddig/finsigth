## نبذة عن المشروع

FinSight تطبيق تجريبي لإدارة دورة مراجعة الفاتورة: رفع مستند، استخراج النص محليًا، اقتراح بعض الحقول من النص، مراجعتها وتصحيحها يدويًا، ثم تسجيل قرار المراجعة أو الاعتماد في سجل تدقيق.

> **الحالة الحالية: نموذج أولي للتطوير المحلي، وليس خدمة إنتاجية.** تُحفظ بيانات الفواتير وبيانات المستندات في PostgreSQL، بينما تُخزّن الملفات على القرص المحلي لخادم API. يدعم المشروع جلسات دخول وأدوارًا ونطاقًا منفصلًا لكل مؤسسة، وOCR محليًا بالإنجليزية والعربية، واقتراحات حقول مبنية على قواعد تسمية بسيطة. هذه الاقتراحات ليست نموذج ذكاء اصطناعي، ولا تمثل تحققًا ماليًا أو إثباتًا لصحة المستند، ولا تُعتمد تلقائيًا. لا ترفع مستندات مالية حساسة إلى نسخة التطوير.

## المزايا الحالية

- إنشاء مساحة عمل خاصة بمؤسسة؛ المستخدم الأول في المؤسسة يصبح مديرًا.
- تسجيل دخول بجلسة موقعة داخل Cookie من نوع HttpOnly وبإعدادات SameSite مناسبة.
- أدوار مدير ومراجع ومشاهد، مع تطبيق الصلاحيات في API.
- عزل سجلات الفواتير والمستندات وعمليات التنزيل حسب المؤسسة المرتبطة بالجلسة.
- تحقق خادمي من حقول الفاتورة والتواريخ ومجاميع البنود والضريبة والإجمالي.
- تخزين PostgreSQL للفواتير وبنودها وبيانات المستندات وسجل المراجعة والتدقيق.
- سجل تاريخي للتعديلات وانتقالات الحالة مع سبب قرار الاعتماد أو الرفض.
- رفع ملفات PDF وJPEG وPNG وWebP بحد أقصى 12 MiB، مع التحقق من توقيع الملف.
- OCR محلي باستخدام Tesseract للإنجليزية والعربية، حتى 20 صفحة PDF، مع حفظ النص وإحداثيات الكلمات ودرجات OCR.
- اقتراح حقول عنوان الفاتورة من النص المستخرج، مع النص الدليلي ورقم الصفحة.
- واجهة ويب لمراجعة الفواتير والحقول ونتائج OCR وإدارة مسار العمل.
- اختبارات وحدة وHTTP وتكامل PostgreSQL اختيارية.

## كيف يعمل استخراج المستند

1. يرفع المستخدم المستند من الواجهة.
2. يتحقق API من نوع الملف وحجمه وتوقيعه، ثم يحفظه في مجلد محلي خاص.
3. يرسل API الملف إلى خدمة OCR المحلية داخل Docker؛ لا يُرسل محتوى المستند إلى خدمة OCR سحابية.
4. تحفظ نتيجة OCR ونص الصفحات ومعلومات الكلمات في PostgreSQL.
5. تحاول قواعد محلية مطابقة تسميات معروفة، مثل رقم الفاتورة والتاريخ والإجمالي، بالإنجليزية وبعض التسميات العربية.
6. تعرض الواجهة الحقول المقترحة مع مصدرها. يستطيع المراجع نقل القيم إلى نموذج الفاتورة ثم مراجعتها وتعديلها بنفسه.
7. لا ينشأ سجل فاتورة ولا تتم الموافقة تلقائيًا عند تشغيل OCR.

**حدود الاقتراحات:** لا توجد حاليًا معالجة AI أو معايرة لدرجات الثقة. قيمة الثقة الحالية مؤشر تقريبي لمطابقة تسمية الحقل، وليست نسبة دقة. قد تفشل القواعد مع تنسيقات غير مألوفة أو تخطيط RTL معقد. البنود التفصيلية لا تُستخرج تلقائيًا. راجع دائمًا المستند الأصلي والقيم المالية يدويًا.

## التشغيل على Windows

### 1. فك الحزمة أو استنساخ المشروع

إذا حمّلت ملف ZIP، فك ضغطه ثم افتح PowerShell في مجلد `FinSight`. أو استنسخ المستودع:

```powershell
git clone https://github.com/muzansiddig/finsigth.git
Set-Location finsigth
```

### 2. تثبيت الاعتماديات

```powershell
npm install
npm --prefix apps/api install
npm --prefix apps/web install
```

### 3. إعداد ملف البيئة

```powershell
Copy-Item .env.example apps/api/.env
```

افتح `apps/api/.env` وغيّر `SESSION_SECRET` إلى قيمة عشوائية خاصة. لتوليد قيمة مناسبة:

```powershell
node -p "require('node:crypto').randomBytes(32).toString('base64url')"
```

لا تشارك السر ولا تضع مستندات حقيقية داخل بيانات التطوير. لا تضف ملفات `.env` إلى Git.

### 4. تشغيل PostgreSQL وOCR

```powershell
docker compose up -d postgres ocr
docker compose ps
```

انتظر حتى تظهر الخدمات بحالة `healthy`. المنافذ المحلية الافتراضية:

- PostgreSQL: `127.0.0.1:55432`
- OCR: `127.0.0.1:58000`

كلمات مرور Compose الحالية مخصصة للتطوير المحلي فقط، ولا تصلح للنشر.

### 5. تطبيق migrations

ينبغي أن يشير `DATABASE_URL` في `apps/api/.env` إلى قاعدة Compose على المنفذ `55432`. بعد التأكد من القيمة، نفّذ:

```powershell
npm --prefix apps/api run db:migrate
```

### 6. تشغيل التطبيق

```powershell
npm run dev
```

- الواجهة: <http://localhost:5173>
- API: <http://localhost:3001>
- فحص صحة API: <http://localhost:3001/api/health>
- فحص اتصال قاعدة البيانات: <http://localhost:3001/api/db/health>

أنشئ مساحة عمل من صفحة الدخول للبدء. الواجهة تعرض شاشة الدخول عند عدم وجود جلسة؛ هذا السلوك طبيعي.

لإيقاف الخدمات المحلية:

```powershell
docker compose stop postgres ocr
```

تظل بيانات PostgreSQL في Docker volume باسم `postgres_data`. لا تستخدم `docker compose down -v` إلا إذا كنت تريد حذف بيانات قاعدة التطوير نهائيًا.

## قاعدة البيانات والترحيلات

مخطط Drizzle موجود في `apps/api/src/db/schema.ts`، وملفات migrations المعتمدة في `apps/api/drizzle`.

توليد migration بعد تعديل المخطط:

```powershell
npm --prefix apps/api run db:generate
```

تطبيق migrations:

```powershell
npm --prefix apps/api run db:migrate
```

يتطلب التشغيل الإنتاجي تحديد `DATABASE_URL` قويًا ومناسبًا للبيئة. لا تعتمد بيانات PostgreSQL الافتراضية أو كلمة مرور Compose عند النشر.

## الاختبارات والبناء

تشغيل اختبارات API والوحدة:

```powershell
npm test
```

تشغيل اختبارات PostgreSQL التكاملية على قاعدة اختبار محلية قابلة للحذف. اضبط عنوان قاعدة البيانات قبل الاختبار:

```powershell
docker exec finsight-postgres createdb -U postgres finsight_test
$env:DATABASE_URL = "postgresql://postgres:postgres@127.0.0.1:55432/finsight_test"
$env:RUN_DB_INTEGRATION_TESTS = "1"
npm test
Remove-Item Env:RUN_DB_INTEGRATION_TESTS
docker exec finsight-postgres dropdb -U postgres finsight_test
```

> استخدم قاعدة اختبار يمكن التخلص منها، ولا توجّه اختبارات التكامل إلى بياناتك. الاختبارات تُنشئ سجلات مؤقتة وتحذفها.

بناء API والواجهة للإنتاج:

```powershell
npm run build
```

يتضمن CI في GitHub Actions اختبارات البناء والتكامل على PostgreSQL مؤقت وتدقيق اعتماديات الإنتاج.

## واجهات API

واجهات البيانات الخاصة تتطلب جلسة دخول عبر Cookie باسم `finsight_session`. يحدد API المؤسسة من الجلسة الموثقة، ولا يثق بمعرّف المؤسسة المرسل في جسم الطلب.

| الطريقة | المسار | الوظيفة |
| --- | --- | --- |
| `GET` | `/api/health` | فحص صحة API |
| `GET` | `/api/db/health` | فحص اتصال PostgreSQL |
| `POST` | `/api/auth/register` | إنشاء مؤسسة وحساب المدير الأول |
| `POST` | `/api/auth/login` | تسجيل الدخول |
| `POST` | `/api/auth/logout` | إنهاء الجلسة |
| `GET` | `/api/auth/me` | معلومات الحساب الحالي |
| `POST` | `/api/invoices/parse` | التحقق من حقول فاتورة مرسلة؛ لا يقرأ ملفًا |
| `GET` / `POST` | `/api/invoices` | عرض فواتير المؤسسة / إنشاء فاتورة للمراجعة |
| `PUT` | `/api/invoices/:id` | تعديل فاتورة وإعادتها إلى المراجعة |
| `PATCH` | `/api/invoices/:id/status` | تغيير حالة الفاتورة مع سبب |
| `GET` | `/api/invoices/:id/history` | عرض سجل مراجعة الفاتورة |
| `GET` / `POST` | `/api/documents` | بيانات المستندات / رفع مستند |
| `GET` | `/api/documents/:id/file` | تنزيل مصرح به لمستند |
| `POST` | `/api/documents/:id/ocr` | تشغيل OCR المحلي وحفظ الحقول المرشحة |
| `GET` | `/api/documents/:id/extraction` | قراءة نتيجة OCR والحقول وأدلتها |

المواصفات التفصيلية ورموز الاستجابة موجودة في [عقد OpenAPI](docs/api/openapi.yaml).

## إعدادات البيئة

يُنسخ `.env.example` إلى `apps/api/.env`. لا تحفظ الأسرار الحقيقية في المستودع.

| المتغير | الاستخدام |
| --- | --- |
| `DATABASE_URL` | عنوان PostgreSQL؛ استخدم `55432` مع Compose المحلي |
| `SESSION_SECRET` | مفتاح توقيع الجلسة؛ مطلوب بطول عشوائي قوي، ولا تستخدم قيمة المثال |
| `PORT` | منفذ API؛ الافتراضي `3001` |
| `NODE_ENV` | نوع البيئة؛ `development` محليًا، و`production` للنشر |
| `UPLOAD_DIR` | مجلد الملفات المحلية؛ الافتراضي `uploads` |
| `WEB_ORIGIN` | أصل الويب المسموح به؛ الافتراضي `http://localhost:5173` |
| `VITE_API_URL` | أصل API اختياري؛ في التطوير يستخدم Vite proxy عند تركه فارغًا |
| `OCR_SERVICE_URL` | عنوان خدمة OCR المحلية؛ الافتراضي `http://127.0.0.1:58000` |

## الأمان والخصوصية

- الملفات المرفوعة مخزنة على القرص المحلي لخادم API، وليست في تخزين كائنات خاص أو مشفر ومهيأ للإنتاج.
- OCR الحالي محلي ولا يرسل الملفات إلى موفّر سحابي.
- لا توجد حاليًا حماية مكتملة من البرمجيات الخبيثة، حصص رفع، سياسة احتفاظ وحذف، أو تحديد معدل لمحاولات الدخول والتسجيل.
- لا تتضمن النسخة الحالية دعوات أعضاء أو تحقق بريد إلكتروني أو MFA.
- نتائج OCR واقتراحات الحقول بيانات غير موثوقة، ويجب مراجعتها يدويًا قبل استخدامها ماليًا.
- لا تنشر التطبيق على الإنترنت ولا تستخدم مستندات مالية حقيقية قبل إغلاق معوقات الأمان والتشغيل الموضحة في [نموذج التهديدات](docs/security/threat-model.md).

## القيود وخطة العمل

من أبرز الأعمال المتبقية قبل الإنتاج:

1. معالجة OCR والاستخراج في طابور خلفي دائم قابل للاستعادة وإعادة المحاولة.
2. تخزين ملفات خاص ملائم للإنتاج مع فحص البرمجيات الخبيثة وسياسة احتفاظ وحذف.
3. إضافة الحصص وتحديد المعدل والتحقق من البريد أو الدعوات، وتوسيع اختبارات الصلاحيات.
4. استكمال استخراج البنود وتقييم الدقة على مجموعة بيانات اصطناعية موثقة للإنجليزية والعربية.
5. إضافة البحث والترقيم والتصفية والتصدير الآمن ولوحات تحليلات مالية.
6. تحسين التسجيل التشغيلي والمراقبة والنسخ الاحتياطي وخطة النشر والاستعادة.

تفاصيل الحالة ومعايير القبول في [خارطة الطريق](docs/roadmap.md).

## استكشاف الأخطاء

### فشل تسجيل الدخول أو رسالة `401`

تحقق من أن تسجيل الدخول تم بنجاح وأن Cookie لم تنتهِ. `401` على `/api/auth/me` قبل تسجيل الدخول متوقع.

### خطأ API `500` أو فشل اتصال قاعدة البيانات

1. تحقق من تشغيل PostgreSQL: `docker compose ps`.
2. تحقق من `DATABASE_URL` في `apps/api/.env` وأن المنفذ يطابق Compose (`55432` افتراضيًا).
3. طبّق migrations: `npm --prefix apps/api run db:migrate`.
4. اختبر `/api/db/health`.

### فشل OCR أو ظهور `503`

تحقق من أن خدمة `ocr` في Compose بحالة `healthy` وأن `OCR_SERVICE_URL` يشير إلى `http://127.0.0.1:58000`. OCR يتطلب Docker image المبنية وخدمات PDF/Tesseract الموجودة فيها.

### تعذّر تحميل الاعتماديات أو بناء صورة OCR

يلزم اتصال إنترنت أثناء التثبيت والبناء الأولي. تحقق من إعداد Docker Desktop والشبكة، ثم أعد الأمر الملائم. لا يلزم الاتصال السحابي لمعالجة المستند بعد تشغيل OCR المحلي.

## المساهمة والترخيص

راجع التوثيق قبل إضافة مزوّد استخراج أو تغيير تدفق المستندات. أضف اختبارات للترحيلات والصلاحيات والبيانات المالية، ولا تضع ملفات مستخدمين أو أسرارًا في الاختبارات أو السجلات.

لم يُحدّد ترخيص للمشروع بعد؛ لا تفترض أن إعادة التوزيع أو الاستخدام التجاري مسموحان قبل إضافة ترخيص صريح.
